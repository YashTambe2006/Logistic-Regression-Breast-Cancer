Breast Cancer Classification Dashboard
A machine learning project using Logistic Regression to classify
breast cancer cases from cell-nuclei measurements, with an interactive
Streamlit dashboard for exploring predictions.
The project brings together data cleaning, exploratory data analysis
(EDA), model training and evaluation, and a user-facing application.
Users can adjust feature values and immediately see the model's
predicted class, output probabilities, and a live measurement-comparison
chart.
Important: This is an educational machine learning project, not a
clinically validated diagnostic system. Predictions must not be used
for medical decisions.

Overview
What the project does
- Analyses the dataset: checks its structure and missing values,
  and explores diagnosis distribution and relationships between
  selected measurements.
- Trains a classifier: uses Logistic Regression to predict the
  diagnosis class from numerical features.
- Evaluates the model: reports accuracy, precision, recall,
  F1-score, and support on a held-out test split.
- Turns the model into an app: provides a Streamlit dashboard
  where feature values can be changed interactively.
- Visualises measurements: displays a Plotly radar chart comparing
  normalized Mean, Standard Error (SE), and Worst measurements for
  selected feature groups.
Dashboard Highlights
- Live prediction: changing a feature slider updates the model
  output automatically.
- Class probabilities: displays the model's output probability for
  Benign and Malignant classes.
- Interactive radar chart: updates with the selected measurements
  to help compare feature patterns.
- Purpose-built interface: dark-themed, two-column dashboard with
  input controls and a dedicated prediction panel.
The displayed probabilities are model outputs, not clinically validated
estimates of cancer risk.

Dataset
The project uses data.csv, containing 569 records and 30
numerical input features, along with an identifier, diagnosis label,
and an extra empty column.
The target column is diagnosis: - B → 0 --- Benign - M → 1 ---
Malignant
The notebook removes the identifier and extra empty column before
modelling. Features describe cell-nuclei measurements, grouped into
Mean, Standard Error (SE), and Worst measurements.
Machine Learning Workflow
1. Load the dataset and inspect its dimensions, data types, and missing
   values.
2. Remove non-predictive identifier and empty columns.
3. Encode diagnosis labels as numeric classes.
4. Perform EDA using diagnosis distribution charts, a radius comparison
   box plot, and a correlation heatmap.
5. Separate input features from the target.
6. Scale numerical features using StandardScaler.
7. Train a Logistic Regression classifier.
8. Evaluate predictions using accuracy and a classification report.
9. Save the trained model and supporting feature information for the
   application.
Evaluation note: In the current notebook, scaling is fitted before
the train/test split. This can introduce data leakage into evaluation.
For a stronger, resume-ready evaluation, split the data first, fit the
scaler only on the training set, and use that fitted scaler to transform
the test set. Re-run evaluation after this change before reporting
performance metrics.

Run Locally
1. Clone the repository
git clone https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
cd YOUR-REPOSITORY
2. Create and activate a virtual environment (recommended)
python -m venv .venv
Windows
.venv\Scripts\activate
macOS / Linux
source .venv/bin/activate
3. Install dependencies
Create requirements.txt with the packages below, then install them:
streamlit
pandas
numpy
matplotlib
seaborn
scikit-learn
joblib
plotly
jupyter
pip install -r requirements.txt
4. Generate the model artifacts
Open breast_cancer.ipynb in Jupyter and run the notebook cells in
order. Confirm that the artifacts/ directory and all six files listed
above have been created.
5. Start the dashboard
From the project root, run:
streamlit run app.py
Open the local URL printed in the terminal, usually
http://localhost:8501.
Limitations and Next Steps

  complete evaluation.
- Use a reproducible, version-pinned requirements.txt.
- Add automated tests and document validated model performance.
- Treat the application as a learning and demonstration tool, not a
  clinical product.
